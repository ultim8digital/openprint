## Source and maintenance

The full English reference is [README.md](../../README.md). [README.en.md](../../README.en.md) is a compatibility link, not an additional edition. The other 49 full editions live in `docs/readme/README.<locale>.md`, including the authored [Russian edition](../readme/README.ru.md).

[The README source blocks](../readme/source.json) contain stable block IDs, English and Russian text, shared commands, protected inline code and link targets. Translate every heading, paragraph and list item. Keep block IDs and placeholder tokens unchanged. Commands and navigation are shared; local file links are resolved relative to each rendered file. A short summary or a link to English is not a substitute for a translated edition.

Update the English source when behavior changes, then update its Russian source and regenerate the other editions. Keep the same sections, commands and link destinations in all editions. Before releasing, check that all 50 files exist, every source block is represented, placeholders match, command blocks are unchanged and local links resolve. The locale list is maintained centrally in [shared/locales.ts](../../shared/locales.ts).

## Review limits

Translations can include machine-generated text. Matching keys, commands and placeholders does not establish fluent or accurate translation, and the project does not claim a native-speaker review of all 50 locales. Corrections from speakers and workshop operators are welcome through [CONTRIBUTING.md](../../CONTRIBUTING.md).

The language menu localizes application text. It does not rewrite user-authored listings, contacts, project documents or every diagnostic produced by external tools. Linked operator and technical guides may remain in their original language; this index covers full README editions rather than translations of every repository document.

## Maintaining interface translations

Author the Russian and English pair at its call site, using named placeholders such as `{count}` for variable text. Run `npm run i18n:extract` to update [src/locales/source.json](../../src/locales/source.json). Each `m_` ID is an FNV-1a hash of the exact Russian/English pair, matching the browser runtime; changing either text creates a new ID. The extractor rejects unresolved dynamic translation calls and hash collisions. English and Russian are authored in the application; the other 48 dictionaries contain every source ID. User content is not part of this catalog.

The isolated [translation runner](../../scripts/translate-locales.py) uses Python's standard library. It does not start a model, a shared coordinator or another application. A default invocation only reports the proposed work. These checks need no provider credentials:

```sh
python3 -B scripts/translate-locales.py --self-test
python3 -B scripts/translate-locales.py --source src/locales/source.json --locales all
```

For an intentional translation run, configure a compatible TranslateGemma completions endpoint in a private file outside Git. Only `MT_SERVER_27B` (the complete HTTPS `/v1/completions` URL), `MT_SERVER_MODEL`, and `MT_SERVER_KEY_FILE` or `MT_SERVER_KEY` are read. Loopback HTTP is allowed for a local model. The file contains literal assignments and is never executed as shell code; environment values override it. No provider is required to build or run OpenPrint with the committed translations. Send only the public source strings to the provider.

Start with a separate pilot output, then set explicit call and scheduling budgets:

```sh
python3 -B scripts/translate-locales.py --config /private/provider.env --probe
python3 -B scripts/translate-locales.py --config /private/provider.env \
  --locales pl,ja,ta-IN --limit 8 --output-dir .local/i18n/pilot \
  --run --max-calls 72 --max-seconds 120 --workers 8
python3 -B scripts/translate-locales.py --config /private/provider.env \
  --locales all --run --max-calls 60000 --max-seconds 1800 --workers 64
```

Run one network coordinator at a time. The call budget includes retries; each string has at most three attempts and each call has an output-token cap. The elapsed-time budget stops scheduling further requests; in-flight requests can finish later under the HTTP timeout. Reported token totals are the provider-reported subset, not a billing statement. Redirects and environment proxies are disabled, and credentials are never written to logs or translation files.

The ignored `.local/i18n` cache is written atomically with private file permissions and is keyed by model, prompt version, locale and the exact source pair. Accepted text is revalidated on reuse. A dictionary is exported only when every source string passes structural checks. Rejected candidates stay in the private report/cache; `--recover-rejected` revalidates them before making further requests. Never relax script, placeholder or numeric checks just to complete a locale. Regional English dictionaries use bounded spelling changes, preserving commands and identifiers.

Record reviewed corrections in [scripts/i18n-reviewed.json](../../scripts/i18n-reviewed.json). Every entry includes `locale`, `id`, exact `en` and `ru` source text, replacement `text`, and the reason. A changed source or duplicate correction fails validation. Corrections override machine output on export and are checked against the committed dictionaries in tests. Once the necessary translations are cached, export corrections with no endpoint, key or network access:

```sh
python3 -B scripts/translate-locales.py --run --cache-only --model tg27 \
  --locales all --recover-rejected --report .local/i18n/ui-export-report.json
```

Use the served model alias that originally populated your cache in place of `tg27`. Missing entries fail instead of falling back silently to English. Structural checks cover placeholders, protected identifiers, Markdown, numbers, unexpected scripts and bounded text; they do not establish semantic accuracy or native fluency. The reviewed registry documents a limited review of selected strings and repairs, not a review of every translation.

The committed [UI translation manifest](ui-translation-manifest.json) records the current source, reviewed registry and dictionary SHA256 hashes, their origins and the review limits. `node scripts/check-i18n-manifest.mjs` verifies those hashes without modifying files or reading a private cache. After an approved source, reference-location, registry or dictionary change, refresh the manifest with the same cache-only command plus `--manifest docs/i18n/ui-translation-manifest.json`; review its origins and limits before committing it. A source-reference-only edit changes the file hash while keeping the pair IDs and cache entries unchanged.

README translations use the same runner with `--source docs/readme/source.json --output-dir docs/readme/locales`. These committed dictionaries contain all 30 translatable blocks; shared commands and navigation come from the source. Source-bound README corrections use a separate registry supplied through `--reviewed`. A complete export can write `docs/readme/translation-manifest.json` with `--manifest`; it records the exact source and dictionary SHA256 hashes, model alias, prompt version and generation time. After approved manual edits, refresh the dictionaries and manifest together. [The renderer](../../scripts/render-readmes.mjs) then produces the full editions without access to an API or private cache.

```sh
node scripts/render-readmes.mjs
npm run i18n:check
npm run check
```

CI and builds read committed source and dictionaries. The `--check` commands verify their consistency without regenerating translations or spending API credits. Keep the manifest, reviewed corrections and actual review limits with the release evidence.
