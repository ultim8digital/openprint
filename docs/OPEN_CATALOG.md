# Открытый каталог без аккаунтов

Начиная с OpenPrint 0.5 основной режим — `APP_MODE=catalog`. У посетителя нет регистрации, пароля или кабинета. Карточки публикуются сразу, без очереди и без модераторов.

## Добавление и обновление студии

1. Найдите студию по названию и городу. Импортированные записи уже доступны в поиске и на карте.
2. Если студии нет, откройте «Добавить студию». Укажите название, город и хотя бы один рабочий контакт — сайт или телефон. Адрес, описание, технологии и материалы можно дополнить.
3. Выберите точку на карте или введите координаты. Геолокация запрашивается только по вашему нажатию. Если координаты неизвестны, запись останется в списке; положение не угадывается по названию города.
4. Подтвердите право публиковать сведения и нажмите кнопку публикации. Карточка сразу станет публичной.
5. Сохраните личную ссылку управления. По ней можно исправлять или удалить только эту карточку. Для просмотра и передачи заказчику используйте обычную публичную ссылку.

Личная ссылка содержит случайный ключ. Любой, у кого он есть, может изменить запись. Храните его приватно; восстановления по почте нет. При открытии редактор убирает ключ из адресной строки и использует приватный заголовок API. Сервер хранит SHA-256 ключа, а не исходный ключ. Ключи не попадают в публичные ответы каталога и карты. Код приложения не журналирует тела запросов и эти заголовки; оператору также следует исключить их из журналов прокси.

Браузер сохраняет ключ управления в хранилище текущей сессии, если оно доступно. На другом устройстве понадобится сохранённая ссылка. Незавершённая публикация использует тот же ключ при повторной отправке: потерянный сетевой ответ не создаёт вторую запись. Сохранение устаревшей версии отклоняется, чтобы две вкладки не перезаписали изменения друг друга.

Удаление снимает карточку с карты, поиска и публичного адреса и очищает её контактные поля. Минимальная запись с хешем ключа, идентификатором, хешем первого запроса и временными отметками сохраняется, чтобы повтор старого запроса не восстановил удалённую карточку. Резервные копии живут по политике владельца сервера.

## Источники и дубли

Импортированные записи сохраняют указание источника; самостоятельные публикации отмечены отдельно. Ни одна из этих меток не удостоверяет принадлежность бизнеса, оборудование или качество услуг.

Дубликат определяется точным совпадением названия, города и адреса после нормализации регистра Unicode. Другая мастерская по другому адресу допустима. Поиск перед публикацией помогает заметить варианты написания, которые точное правило не распознаёт. Проверка дубля и запись выполняются одной транзакцией. Импорт, конфликтующий с самостоятельной публикацией, отклоняется целиком; он не присваивает её и не меняет личный ключ.

Импортированную карточку нельзя захватить через публичную форму. Для её исправления владелец экземпляра обновляет исходный каталог через [импорт](CATALOG_IMPORT.md). Самостоятельно добавленная студия управляет своей записью по ключу.

## Автоматические ограничения

Без ручной модерации действуют технические ограничения:

- До 5 новых карточек с одного IP за скользящие 24 часа и до 200 на экземпляр за тот же период. Квоты успешных публикаций переживают перезапуск. Общий IP офиса может разделять одну квоту.
- До 50 000 идентификаторов самостоятельных публикаций, включая удалённые. Карта показывает до 50 000 подходящих точек и сообщает об усечении.
- Дополнительные краткосрочные ограничения запросов на создание, чтение ключом и редактирование. Это не распределённая защита от DDoS и не проверка личности.
- Ограниченные длины полей, только HTTP(S)-сайты без встроенных паролей, допустимая пара координат, обязательный сайт или телефон, проверка Origin для изменений.

Для суточной квоты IP хранится в виде HMAC с отдельной случайной солью экземпляра. Устаревшие записи квоты удаляются при следующей попытке публикации; исходные IP приложение в эту таблицу не сохраняет. Обратный прокси может вести собственные журналы.

## GitHub и запуск

Код, инструкции и релизы доступны на [GitHub](https://github.com/ultim8digital/openprint) под MIT. Каждый может создать fork и свой экземпляр. [GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages) обслуживает статические страницы; этому приложению для общих записей нужен Node.js API и SQLite на работающем сервере. Размещение исходников на GitHub не публикует автоматически работающий API или данные конкретного экземпляра.

Установка: [SELF_HOSTING.md](SELF_HOSTING.md). Vercel, Supabase, SMTP и платные API не нужны. `APP_MODE=community` отдельно включает прежние проекты и CAD с их аккаунтами и правами. Режим каталога не показывает эти разделы, не отдаёт их API и не запускает очередь CAD. Переключение не удаляет данные.
