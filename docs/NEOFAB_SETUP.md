# Neofab Studio: запуск, CAD и подключение ИИ

Studio — рабочее место для подготовки производственного проекта внутри OpenPrint. Оно открывается по `/studio` после входа. Общая архитектура CAD/CAM-платформы — в [NEOFAB_BLUEPRINT.md](NEOFAB_BLUEPRINT.md), коммерческая модель — в [NEOFAB_BUSINESS.md](NEOFAB_BUSINESS.md).

## Попробовать без ключей

```sh
npm ci
npm run demo
```

Откройте `http://localhost:5173`, выберите вымышленного заказчика в верхней полосе и нажмите «Создать с Neofab». Демо работает только локально. Для настоящего сообщества используйте [обычную установку](SELF_HOSTING.md).

1. Опишите задачу: функциональную деталь, запасную часть, мебель, сборку или серию изделий.
2. Выберите задачу: проектирование/консультация или расчёт изготовления. Заполните назначение, количество изделий и город; добавьте состав, материалы, операции и критерии приёмки. Количество компонента задаётся **на одно готовое изделие** и может оставаться неизвестным.
3. Внесите подтверждённые факты в требования. Открытые вопросы и допущения сохраните для обсуждения со специалистом — они попадут в заявку с явными пометками.
4. При необходимости добавьте CAD: загрузите учебный пример или собственную JSON-спецификацию, задайте параметры и компоненты, сохраните ревизию и запустите построение. Просмотрите сборку и замечания отчёта. Изменение ТЗ требует пересборки CAD для новой версии.
5. Сохраните и подтвердите точную версию ТЗ и CAD-комплекта для обсуждения и расчёта. Выберите мастерскую или опубликуйте открытую заявку. Подтверждение не разрешает производство. Публикация фиксирует комплект; повтор запроса возвращает ту же заявку.
6. Продолжите в заявке: вопросы исполнителю, предложение, согласование точных условий, изготовление и приёмка.

Без API остаются доступны редактирование, состав изделия, подбор, экспорт, публикация и локальный CAD при установленном движке. Без Python работают три простых FDM-шаблона: блок, пластина и втулка. Их размеры задаёт пользователь. Простой шаблон и декларативный CAD нельзя одновременно прикрепить к одному проекту: перед сменой способа моделирования удалите прежний вариант. Задачи других технологий можно передавать специалисту как ТЗ; наличие модели не означает готовности CAM.

В прототипе допускается до 200 рабочих проектов на аккаунт и 100 ревизий одного проекта. История текста ревизий ограничена 20 MiB на аккаунт и 200 MiB на экземпляр. Повторное сохранение того же содержимого не создаёт новую ревизию. При достижении предела запись отклоняется, существующая история сохраняется; это лимиты данных Studio, а не точный предел размера файла SQLite с индексами и журналом WAL.

## Подключить локальный CAD

Установите Python 3.12 и зависимости в отдельное окружение проекта:

```sh
python3.12 -m venv cad-worker/.venv
cad-worker/.venv/bin/python -m pip install -r cad-worker/requirements.txt
cad-worker/.venv/bin/python cad-worker/worker.py --check
CAD_PYTHON="$PWD/cad-worker/.venv/bin/python" npm run demo
```

Для постоянной установки добавьте в серверный `.env` переменную `CAD_PYTHON` с **абсолютным путём** к этому Python и перезапустите приложение. Существующий `.env` сохраняйте. В браузер путь и секреты окружения не передаются. Признак подключения в интерфейсе означает настройку исполнителя; успешное построение подтверждает работоспособность конкретного задания.

Вариант с Docker включает CAD в образ приложения:

```sh
docker compose -f compose.yaml -f compose.cad.yaml up --build -d
```

При обновлении работающего сообщества сначала выполните остановку и резервное копирование по [SELF_HOSTING.md](SELF_HOSTING.md). Обычный Compose-образ сохраняет лёгкую установку без Python.

Движок строит до 24 физических компонентов и 300 операций из блоков, цилиндров, выдавливаний, скруглений и фасок. Каждая физическая копия — отдельный компонент. Результат включает STEP/STL сборки и деталей, BOM CSV, JSON-спецификацию, сетку просмотра, отчёт и ZIP-комплект с SHA-256. Учебные размеры не подставляются в проект без выбора примера пользователем. Подробнее — [CAD_ENGINE.md](CAD_ENGINE.md).

По умолчанию допускаются 30 запусков за всё время проекта; за последние 24 часа — 10 на пользователя и 100 на экземпляр. Одновременно работает один CAD-процесс; у пользователя может быть одно ожидающее или выполняющееся задание. Неуспешные и отменённые запуски учитываются. Удаление аккаунта не стирает суточный счётчик экземпляра. Повтор запроса и повтор запуска уже построенной текущей версии не создают новое вычисление.

Спецификация ограничена 90 000 байтами, JSON-тело HTTP-запроса — 96 KiB. Результат ограничен 32 MiB на файл и 128 MiB на сборку; зарегистрированные CAD-артефакты — 256 MiB на пользователя и 2 GiB на экземпляр. Перед запуском резервируется верхний предел результата. Эти лимиты независимы от обычных загрузок и не включают накладные расходы SQLite, WAL, резервные копии и временные файлы.

Для нативного процесса установлены 90 секунд CPU и 120 секунд общего времени; на Linux также 3 GiB виртуальной памяти. На macOS такого ограничения памяти нет. Это ограниченный запуск доверенного компилятора, а не полная изоляция файловой системы и сети. Приложение передаёт только JSON и очищенное окружение, не исполняя пользовательский Python. После перезапуска ожидающие актуальные задания продолжаются, прерванные получают ошибку и требуют явного повтора.

## Передать CAD исполнителю

Адресат **личной заявки** получает подтверждённый CAD-комплект сразу при отправке. В открытой заявке файлы остаются закрытыми: заказчик может открыть комплект конкретному участнику обсуждения для расчёта. Доступ можно отозвать до выбора исполнителя; выбранный исполнитель сохраняет доступ к согласованному комплекту. Публичный каталог моделей — отдельный механизм с отдельным согласием и лицензией.

Проверьте STEP, отдельные детали, состав и замечания вместе со специалистом. Отчёт проверяет геометрию и явно заявленные размеры/пересечения, но не прочность, технологические допуски, доступ инструмента или пригодность изделия. Замечания и незавершённая геометрия могут оставаться в комплекте для обсуждения. Каждая выдача относится к зафиксированной версии, а не к изменяемому рабочему черновику.

## Подключить OpenAI на своём сервере

Если `.env` ещё нет, создайте его из `.env.example`. Существующий файл не перезаписывайте. Внесите ключ **локально в серверный `.env`** или в секреты окружения вашего хостинга:

```dotenv
OPENAI_API_KEY=your-server-key
OPENAI_MODEL=gpt-6-luna
OPENAI_REVIEW_MODEL=gpt-6.1-sol
OPENAI_CAD_MODEL=gpt-6.1-sol
STUDIO_AI_MAX_PROJECT_CALLS=3
STUDIO_AI_MAX_USER_DAILY_CALLS=10
STUDIO_AI_MAX_DAILY_CALLS=50
STUDIO_AI_MAX_OUTPUT_TOKENS=3000
STUDIO_AI_CAD_MAX_OUTPUT_TOKENS=8000
```

Ключ не нужен в браузере, GitHub, `VITE_*` или тексте проекта. Указанные идентификаторы моделей — настраиваемые значения по умолчанию; доступность конкретной модели в вашем API-проекте нужно проверить реальным вызовом. Скриншот баланса и наличие ключа не доказывают такой доступ.

Перезапустите `npm run dev` либо `npm start`. Docker Compose передаёт перечисленные переменные контейнеру; после изменения окружения пересоздайте контейнер с теми же Compose-файлами, которые использовали при запуске. Версия 0.3 обновляет SQLite со схем 1–3 до схемы 4, сохраняя существующие проекты. Откат старого приложения выполняется восстановлением совместимой резервной копии.

Внутри проекта помощь ИИ вызывается отдельно, после согласия на передачу текста. Сервер выбирает модель по задаче:

| Задача              | Настройка             | Начальное значение                  |
| ------------------- | --------------------- | ----------------------------------- |
| Уточнение ТЗ        | `OPENAI_MODEL`        | `gpt-6-luna`                        |
| Подробный разбор ТЗ | `OPENAI_REVIEW_MODEL` | `gpt-6.1-sol`                       |
| Предложение CAD     | `OPENAI_CAD_MODEL`    | Наследует модель подробного разбора |

Это фиксированная маршрутизация по действию пользователя. Автоматической оценки сложности, каскада субагентов и перехода на более дорогую модель после ошибки нет. Модель для отдельного запроса нельзя подменить из браузера. Начальные роли согласуются с описаниями [Luna](https://developers.openai.com/api/docs/models/gpt-6-luna) и [Sol](https://developers.openai.com/api/docs/models/gpt-6.1-sol); качество CAD нужно проверять на собственных задачах. Настройки этого приложения не изменяют модели агентов в Orca.

ИИ получает исходную идею, текущий черновик и дополнительное указание. Для CAD также передаётся сохранённая декларативная спецификация. Загруженные файлы, email, сессия и чужие проекты ему не передаются. Ответ проходит проверку структуры и правил приложения. После ответа нужно проверить изменения и подтвердить новую версию. ИИ не публикует заявку и не управляет оборудованием.

## Получить предложение CAD

1. Сохраните ТЗ и текущие правки CAD. Если прикреплён простой FDM-шаблон, удалите его и сохраните ТЗ перед переходом к декларативному CAD.
2. В CAD-панели опишите нужную геометрию и измеренные размеры, подтвердите отправку текста провайдеру и запросите предложение. Для неполной задачи ожидаются вопросы, а не выдуманные размеры.
3. Проверьте описание, компоненты, размеры, допущения, вопросы и JSON. Генерация предложения не изменяет сохранённый CAD и не выполняет построение. Можно продолжать ручное редактирование; после изменения исходной версии старое предложение нельзя применить.
4. После проверки отдельно примените предложение. Это создаёт ревизию CAD и снимает прежнее подтверждение проекта. Затем запустите локальное построение, осмотрите результат и согласуйте комплект с инженером или мастерской.

Модель может ошибиться и при корректном JSON. Проверка схемы проверяет формат, диапазоны и ограничения декларативной геометрии, но не доказывает соответствие намерению пользователя. Неполное предложение может содержать только вопросы. Недоступность модели, отказ, превышение времени или лимита не запускают другой платный запрос автоматически.

## Ограничение расходов и наблюдение

По умолчанию разрешены 3 попытки на проект, 10 на пользователя за последние 24 часа и 50 на экземпляр за последние 24 часа. Одновременно выполняется не более одного запроса пользователя и двух запросов экземпляра. Неудачная или прерванная попытка тоже учитывается: сервер не может гарантировать, что провайдер не выполнил запрос. Повтор одного идентификатора запроса не вызывает API снова.

Журнал сохраняет модель, статус, время и фактически возвращённое провайдером число входных/выходных токенов. Если ответ или данные usage не получены, нулевое значение означает отсутствие измерения, а не доказанно бесплатный вызов. После удаления аккаунта минимальный журнал остаётся для лимита экземпляра, без текста ТЗ.

Это **лимиты попыток и токенов, а не денежный бюджет**. В текущей версии нет тарификации, баланса пользователя, цены заказа или гарантированного долларового потолка. Денежное резервирование, счётчики расходов по тарифам и пакетные задания описаны как следующий этап в архитектуре.

Первую проверку API проводите на небольшом вымышленном проекте: вызовите «Уточнение», проверьте ответ, статус и usage. Затем отдельно проверьте отказ/недоступность модели и сохранность ручного пути. Автотесты репозитория используют тестовый транспорт и не расходуют API-баланс. Выполненный live API-вызов этой сборки не заявлен в [VALIDATION.md](VALIDATION.md).

Для воспроизводимой проверки CAD есть `npm run ai:eval -- --case all`: по умолчанию это план без API-вызовов. Отдельный флаг `--live` запускает до трёх платных запросов с численными проверками локального ядра. Порядок запуска и границы проверки — в [AI_EVALUATION.md](AI_EVALUATION.md).

## Границы текущей реализации

Один проект Studio публикует одну заявку одному выбранному исполнителю либо открытому кругу участников. Список компонентов ТЗ пока плоский; производственные операции — последовательность текстовых пунктов. CAD имеет отдельную декларативную историю геометрии. Разделение заказа между цехами, зависимости производственных операций, импорт чертежей или произвольного STEP в редактируемую геометрию, FEA, слайсинг и машинные постпроцессоры не реализованы. ИИ предлагает ограниченную CAD-спецификацию; применение, построение и публикация остаются отдельными действиями.

Совпадение профиля по технологии/материалу/городу помогает выбрать собеседника; оно не подтверждает оборудование, допуски, мощность или производственную готовность. Подтверждение версии фиксирует согласованное ТЗ и не заменяет инженерную проверку.

Техническая основа ИИ: [Responses Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses). Политика обработки данных и граница `store: false`: [OpenAI API data controls](https://developers.openai.com/api/docs/guides/your-data), [PRIVACY.md](../PRIVACY.md).
