# Проверить ИИ-конструктора на своём API

Автотесты приложения проверяют права, версии, лимиты и обработку ответов через тестовый транспорт. Они не измеряют качество живой модели. Скрипт `ai:eval` проверяет тот же серверный запрос CAD на трёх небольших вымышленных задачах и, для геометрических результатов, запускает настоящее локальное ядро.

## Сначала посмотреть план без запросов

```sh
npm run ai:eval -- --case all
```

Без `--live` скрипт не обращается к API, не строит CAD и не создаёт отчёт. Он показывает модель, число потенциальных запросов, максимальное число выходных токенов, исходные данные и ожидаемые результаты. Значение ключа никогда не печатается.

| Пример               | Проверка                                                                                           |
| -------------------- | -------------------------------------------------------------------------------------------------- |
| `plate`              | Пластина 80×50×6 мм с одним сквозным отверстием Ø8: 1 тело, габариты и аналитический объём         |
| `assembly`           | Два отдельных блока 20×10×5 мм, смещённых по X: 2 тела, общие габариты 60×10×5 мм и объём 2000 мм³ |
| `missing-dimensions` | Неизвестная форма и размеры: результат `spec=null` и уточняющие вопросы                            |

## Явно запустить платную проверку

Настройте `OPENAI_API_KEY`, модель и `CAD_PYTHON` локально по [инструкции](NEOFAB_SETUP.md). Геометрические примеры проверяют доступность ядра до обращения к провайдеру. Начните с одного:

```sh
npm run ai:eval -- --case plate --live
```

Для всех трёх:

```sh
npm run ai:eval -- --case all --live
```

Один пример делает не более одного вызова, полный набор — не более трёх. После первого неуспешного результата выполнение прекращается, автоматических повторов и исправлений нет. По умолчанию предел ответа CAD — 8000 токенов. Указанные ограничения не являются денежным потолком; перед запуском проверьте тариф своего API-проекта. Это отдельный операторский инструмент с собственным небольшим набором задач: он не расходует счётчик заявок сообщества и не использует его журнал.

Отчёт сохраняется с приватными правами в `.local/ai-eval/<run>/report.json`, вне Git. Он содержит фактическое использование токенов, если провайдер вернул его, предложение модели, численные результаты и длительность. Ошибки и отсутствие `usage` не означают бесплатность запроса. При обычном завершении временные STEP/STL удаляются после геометрической проверки; спецификация и отчёт остаются. Принудительная остановка процесса может прервать запись отчёта и оставить временные файлы в приватной папке запуска. В таком случае проверьте расход в кабинете провайдера перед повтором.

## Как читать результат

`PASS` означает прохождение конкретных проверок этого примера. Габариты, число тел и объём не доказывают положение каждого элемента, правильность всей конструкции или пригодность к эксплуатации. Просмотрите спецификацию вручную и воспроизведите её через Studio, затем проверьте геометрию и передачу комплекта исполнителю. Для изменения модели повторяйте один и тот же набор и сравнивайте качество, исправления, задержку и расход.

Для коммерческого пилота добавьте собственные измеренные детали, неизвестные и противоречивые размеры, посадки, отрицания, единицы и повторяющиеся компоненты. Качество реального изделия подтверждают изготовление и измерения. Ни три примера, ни тестовый транспорт не подтверждают готовность всех CAD/CAM-технологий.

Проверка текущей сборки: dry-run выполнен; живые платные запросы не выполнялись, API-ключ в рабочем окружении не настроен. Актуальные результаты — в [VALIDATION.md](VALIDATION.md).
