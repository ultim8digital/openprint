# OpenPrint

**मुद्रण स्टुडिओ आणि कार्यशाळांची एक मुक्त निर्देशिका. येथे नोंदणी करण्याची किंवा व्यवस्थापकांची आवश्यकता नाही.**

[Languages / Языки](../../docs/i18n/README.md) · [English](../../README.md) · [Русский](../../docs/readme/README.ru.md)

नकाशामध्ये एखादे उत्पादन युनिट शोधा, त्यांच्या क्षमता तपासा आणि थेट संपर्क साधा. जर तुमच्या कार्यशाळेची माहिती नसेल, तर तिची संपर्क माहिती आणि सेवांची माहिती जोडा: ती माहिती त्वरित दिसेल. तुमची माहिती संपादित करण्यासाठी किंवा हटवण्यासाठी, खाजगी व्यवस्थापन लिंक जतन करा. डीफॉल्ट कॅटलॉगमध्ये कोणतेही खाते, ईमेल पडताळणी किंवा मंजुरी प्रक्रिया नाही.

OpenPrint ला Node.js 24 आणि स्थानिक SQLite सह चालवा. Vercel, Supabase, ईमेल पुरवठादार, सशुल्क एआय आणि तृतीय-पक्ष लॉगिन आवश्यक नाही. GitHub हे स्रोत आणि प्रकाशन होस्ट करते; सामायिक वेबसाइट, ज्यामध्ये सबमिशन स्वीकारले जातात, त्यासाठी चालू API सर्व्हर आवश्यक आहे. केवळ [GitHub पृष्ठे](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages) Node.js API चालवू शकत नाहीत किंवा अभ्यागतांनी केलेल्या बदलांना जतन करू शकत नाहीत.

## कॅटलॉगची वैशिष्ट्ये

- नाव, शहर आणि तंत्रज्ञान वापरून शोधा. नकाशावर यादीतील पृष्ठांकनाकडे दुर्लक्ष करून जुळणारी ठिकाणे दर्शविली जातात.
- खाते तयार न करता प्रकाशित करा. नकाशावरील एखादे ठिकाण निवडा किंवा अक्षांश आणि रेखांश प्रविष्ट करा; अक्षांश आणि रेखांश नसलेल्या नोंदी शोधता येतील.
- एका सूचीतील माहिती संपादित करा किंवा ती हटवा, तसेच त्या सूचीसाठी असलेला खाजगी दुवा (लिंक) वापरा. आवृत्ती तपासणीमुळे वेगवेगळ्या टॅबमध्ये एकाच वेळी केलेले बदल एकमेकांशी विसंगत झाल्यास ते टाळता येते.
- प्रकाशित करण्यापूर्वी आधीपासून असलेल्या स्टुडिओ शोधा. तंतोतंत नाव, शहर आणि पत्ता जुळणारे कोणतेही स्टुडिओ आपोआप नाकारले जातील.
- स्त्रोताचा उल्लेख करून कॅटलॉग आयात करा. ऑपरेटरद्वारे केलेले आयात स्वतः प्रकाशित केलेल्या याद्यांवर अधिलेखित करू शकत नाही.
- कोणत्याही API कीशिवाय OpenStreetMap टाइल्स पहा. नकाशा प्रदर्शित झाल्यावर टाइल्स लोड होतात, ज्यात डीफॉल्ट लँडिंग पेजचाही समावेश असतो.
- भाषा मेनूमधून इंटरफेसची भाषा निवडा. वरील भाषा निर्देशिकेतून तुमच्या भाषेत दिलेली संपूर्ण ‘रीडमी’ (README) वाचा.

प्रकाशन व्यवसायाच्या मालकीची किंवा सेवेच्या गुणवत्तेची पडताळणी करत नाही. उपकरणांची माहिती, क्षमता आणि अटी स्टुडिओकडून तपासा. ज्यांच्याकडे खाजगी व्यवस्थापन लिंक आहे, ते त्या माहितीवर नियंत्रण ठेवू शकतात. ती माहिती खाजगी ठेवा; ईमेल पुनर्प्राप्तीची सोय नाही. [स्वयं-प्रकाशन मार्गदर्शिका](../../docs/OPEN_CATALOG.md) वाचा.

## तुमचे स्वतःचे उदाहरण चालवा

Node.js 24 स्थापित करा, हे रिपॉझिटरी क्लोन करा आणि चालवा:

```sh
npm ci
npm run build
cp .env.example .env
npm start
```

ओपन `http://localhost:3000`. डीफॉल्ट `APP_MODE=catalog` साठी प्रशासक किंवा वापरकर्ता सेटअपची आवश्यकता नाही. [सेल्फ-होस्टिंग मार्गदर्शिका](../../docs/SELF_HOSTING.md) वापरून `APP_URL`, HTTPS आणि बॅकअप कॉन्फिगर करा. Docker कंपोज देखील उपलब्ध आहे: `docker compose up --build -d`.

समर्थित उपयोजन (deployment) म्हणजे एका लोकल डिस्कवर SQLite सह एक ॲप्लिकेशन प्रक्रिया. स्वयंचलित प्रकाशन आणि विनंती कोटांमुळे गैरवापर मर्यादित होतो, यासाठी कोणत्याही मध्यस्थीची आवश्यकता नाही. सामायिक ऑफिस आयपी (IP) एका प्रकाशनाच्या कोट्यामध्ये सामायिक केले जाऊ शकते. सार्वजनिक उदाहरण उघडण्यापूर्वी [मर्यादा आणि व्यवस्थापन-लिंक वर्तन](../../docs/OPEN_CATALOG.md) तपासा.

विद्यमान डेटासेटवरील अधिकार तपासल्यानंतर [कॅटलॉग आयात CLI](../../docs/CATALOG_IMPORT.md) वापरा. प्रत्येक इंस्टन्सचा डेटासेट, अपलोड केलेल्या फाइल्स आणि बॅकअप रिपॉझिटरी किंवा कंटेनर इमेजमध्ये समाविष्ट नसतात.

## ऐच्छिक समुदाय आणि Neofab मोड

खाजगी प्रकल्प, पुरवठादारांची कोटेशन, मॉडेल लायब्ररी आणि Neofab स्टुडिओ सक्षम करण्यासाठी `APP_MODE=community` स्पष्टपणे सेट करा. या कार्यप्रणाली स्वतःची खाती आणि परवानग्या वापरतात. मोड बदलल्यास साठवलेला डेटा जतन केला जातो. कॅटलॉग मोडमध्ये, API द्वारे खाजगी समुदायाचा इतिहास उघड केला जात नाही किंवा थांबलेल्या CAD कामाला पुन्हा सुरू केले जात नाही.

[Neofab स्टुडिओ](../../docs/NEOFAB_SETUP.md) आवृत्तीनुसार बदलणाऱ्या उत्पादन माहितीपत्रकांचे, आवश्यक सामग्रीच्या याद्यांचे आणि मर्यादित घोषणात्मक CAD चे समर्थन करते, तसेच STEP/STL स्वरूपात डेटा निर्यात करण्याची सुविधा देते. CAD आणि कृत्रिम बुद्धिमत्ता (AI) ऐच्छिक आहेत. AI-आधारित प्रस्तावांचे पुनरावलोकन करणे आवश्यक आहे आणि त्यासाठी स्वतंत्र अर्ज प्रक्रिया आहे; ते आपोआप ऑर्डर प्रकाशित करत नाहीत किंवा भूमिती तयार करत नाहीत. CAM, जी-कोड आणि प्रत्यक्ष उत्पादन पडताळणीची सुविधा सध्या उपलब्ध नाही.

## डेटा अधिकार आणि गोपनीयता

MIT सॉफ्टवेअर परवाना आयात केलेल्या व्यावसायिक नोंदींवरील अधिकार देत नाही. केवळ स्रोताचा उल्लेख केल्याने Google Maps, 2GIS, Yandex Maps किंवा इतर स्रोतांमधून डेटा कॉपी करण्याची परवानगी मिळत नाही. डेटासेट वापरण्यापूर्वी साठवण, प्रकाशन आणि पुनर्वितरणासाठी परवानग्या तपासा. [डेटाचा उगम आणि परीक्षणाच्या मर्यादा](../../docs/DATA_PROVENANCE.md) पहा.

स्वतःहून प्रकाशित केलेली संपर्क माहिती सार्वजनिक असते; व्यवस्थापन की (keys) खाजगी असतात. डेटाबेस आणि बॅकअप्स सार्वजनिकरित्या उपलब्ध असलेल्या निर्देशिकांच्या बाहेर ठेवा आणि सुधारणा आणि हटवण्याच्या विनंत्यांसाठी संपर्क व्यक्ती द्या. अंमलबजावणी करण्यापूर्वी [गोपनीयता](../../PRIVACY.md) आणि [सुरक्षा](../../SECURITY.md) धोरणे वाचा.

## विकास आणि भाषांतर

```sh
npm run dev
npm run check
npx playwright install chromium
npm run test:e2e
npm run format:check
```

GitHub ॲक्शन प्रकार, API आणि ब्राउझर वर्कफ्लो तपासते, तसेच डीफॉल्ट आणि मूळ CAD कंटेनर तपासते. चाचणीसाठी काल्पनिक नोंदी वापरल्या जातात. अचूक पुरावा, व्याप्ती आणि उर्वरित मर्यादा [व्हॅलिडेशन](../../docs/VALIDATION.md) आणि [उत्पादन व्याप्ती](../../docs/PRODUCT.md) मध्ये नोंदवल्या जातात.

इंग्रजी README हे पूर्णपणे भाषांतरित केलेल्या आवृत्त्यांसाठी संदर्भ आहे. [भाषा निर्देशांक](../../docs/i18n/README.md) भाषांतर व्यवस्थापन आणि पुनरावलोकन मर्यादांची माहिती देतो. इंटरफेसचे भाषांतर करताना, वापरकर्त्यांनी तयार केलेल्या याद्या, प्रकल्पातील सामग्री किंवा प्रत्येक बाह्य तांत्रिक माहितीचे भाषांतर केले जात नाही.

[तृतीय-पक्ष सूचना](../../THIRD_PARTY_NOTICES.md) पहा.
